# Manga Checker

BOOK☆WALKERのシリーズIDから漫画の最新巻・配信開始日・配信予定日を取得し、PC・スマホで確認する個人用Webアプリ。

- 公開ページ: https://cimavip5.github.io/manga-checker/
- 最新巻データ: `data.json`（GitHub Actionsで原則1日1回更新）
- 登録作品一覧: `series.json`（シリーズIDと作品名）
- 対象リポジトリ: `cimavip5/manga-checker`

## Webから作品を登録する

1. 公開ページの「作品を登録」にBOOK☆WALKERの**シリーズID**を入力する。
2. **1行に1ID**入力する。1件でも複数件でも登録可能。複数件の一括登録は**最大30行**（空行を除く）。
3. 「登録に進む」を押し、開いたGitHubのIssue作成画面で内容を確認する。
4. リポジトリ所有者 `cimavip5` のGitHubアカウントで **Submit new issue** を押す。
5. GitHub ActionsがIDを確認し、追加可能なシリーズを登録して最新巻データを更新する。正常終了後、Issueに結果コメントが付き、Issueが閉じられる。

**登録許可:** 登録用ワークフローはIssueの作成者がリポジトリ所有者の場合だけ実行する。他人が同じ形式のIssueを作っても登録処理は動かない。GitHubログインが必要で、Webページ自体に別の認証方式は設けていない。

**入力形式:** IDは先頭0を除く1～10桁の数字。例: `114834`。作品名やシリーズのURLをそのまま入力する方式ではない。複数行のうち不正なIDは失敗として記録され、他の有効IDの処理は続行する。

## 登録処理のルール

- **1件登録:** Issueタイトル `manga-register: 114834`。従来の1件登録方式を維持。
- **一括登録:** Issueタイトル `manga-register: bulk`。Issue本文はシリーズIDを1行に1件ずつ記載する。
- 既存の`series.json`にあるIDは**登録済み**としてスキップ。
- 同じ入力内で重複したIDは、最初の出現だけを処理し、残りは**入力内重複**としてスキップ。
- BOOK☆WALKERからの取得に失敗したIDは**取得・入力失敗**として記録し、残りのIDの処理を続行。
- 新規登録できた作品だけを`series.json`に追記。元の登録作品は削除せず、新規登録がなければ同ファイルは書き換えない。
- **新規登録／登録済み／入力内重複／取得・入力失敗**をそれぞれ集計し、IDごとの内訳をGitHub Actionsの実行サマリーとIssueコメントへ出力する。
- 一括登録の本文が空、または有効な空行除外後の入力が30行を超える場合は処理全体を停止する。失敗時にはIssueは自動クローズされない。
- ワークフロー内の最新巻更新やGitHubへの保存が失敗した場合もIssueは自動クローズされない。結果が反映されたか、ActionsログとGitHub上のファイルを確認する。

## 主なファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | 作品一覧、検索・並び替え、1件／複数件の登録入力 |
| `scripts/register.py` | IDの解析、重複判定、BOOK☆WALKERからのシリーズ名取得、結果報告 |
| `.github/workflows/register.yml` | 所有者確認、Issueの登録依頼処理、最新巻更新、結果コメント |
| `scripts/update.py` | 各シリーズの最新巻・配信日取得 |
| `series.json` | 登録シリーズのID・作品名 |
| `data.json` | Web表示用の取得結果 |

## 確認と注意

- 登録結果はGitHubのIssueコメント／Actionsログ、および更新後の`series.json`で確認する。
- 公開ページの`data.json`反映にはタイムラグが生じる場合がある。必要に応じてページの「表示を更新」を利用する。
- データはBOOK☆WALKERのページ構造に依存する。取得失敗や取得値の不一致があれば、対象シリーズのページを確認する。
- シリーズIDはマンガ版・小説版・別シリーズで異なることがある。大量登録時も、IDと作品の対応を確認してからIssueを確定する。
- 所持巻管理、五十音分類、名称の整形などは今後の課題。現時点では実装しない。
